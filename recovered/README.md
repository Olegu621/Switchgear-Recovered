# Switchgear 69.252 v3.2 — восстановленные материалы проекта

Из предоставленного APK восстановлен **редактируемый проект smali + Android-ресурсы**, который успешно пересобран в APK. Также сохранены читаемая Java-декомпиляция, игровые данные, оригинальные библиотеки, распакованный машинный код FUSION и C-подобный псевдокод.

Это восстановление из скомпилированного приложения. Исходный репозиторий C/C++/Java/Kotlin один к одному не возвращён: комментарии, исходные имена после обфускации, структура Gradle и исходники сервера в APK отсутствуют. Для пересборки используются сохранённые нативные библиотеки, а не автоматически полученный C-псевдокод.

Исходный APK на рабочем столе не изменён.

## Как собрать

Откройте PowerShell в этой папке:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\rebuild.ps1
```

Java 17 включена как переносимый ZIP и при первом запуске извлекается в `tools/.runtime/`. Установка Java или Android Studio для этой сборки не требуется.

Результат — `artifacts/Switchgear-69.252-v3.2-rebuilt-unsigned.apk`. Готовый тестовый APK не включён в архив исходников, чтобы не дублировать ещё 1,8 ГБ.

При желании можно использовать свою Java:

```powershell
.\tools\rebuild.ps1 -Java 'C:\path\to\java.exe'
```

Сборка выполняется из smali, ресурсов и исходных библиотек. Каталог `java/` предназначен для чтения и реконструкции кода; это не готовый Gradle-проект, который можно сразу скомпилировать из Java.

APK будет без подписи. Для установки его необходимо подписать. Для обновления существующей установки с сохранением её идентичности требуется прежний ключ подписи, которого в APK нет. Проверки подписи и целостности внутри приложения могут влиять на работу пересобранной версии. Запуск пересобранного APK на Android не проверялся.

## Где начинается логика загрузчика

Пути относительно `java/sources/`:

- `com/supercell/titan/KkGateActivity.java` — стартовый экран, запуск потока `fusion-start`, ожидание результата и переход в игру.
- `com/supercell/titan/KkRestartActivity.java` — отдельный процесс перезапуска.
- `com/supercell/titan/KkProgressBridge.java` — мост обновления прогресса.
- `zap/C2540m.java` — исходный класс `zap.m`, загрузка `System.loadLibrary("FUSION")` и вызов нативного старта.
- `zap/` — Java-объявления нативных методов и интерфейсы загрузчика.
- `com/supercell/titan/TitanApplication.java` — загрузка базовых библиотек и жизненный цикл приложения.
- `com/supercell/brawlstars/GameApp.java` — игровая Activity.

Переименования JADX записаны в `evidence/jadx-names.jobf`. В smali сохранены дескрипторы классов из DEX, включая имена с отличающимся регистром, которые Apktool размещает в файлах с суффиксом `.1` для Windows.

## Нативная часть

В `libFUSION.a.do` найден JPEG-контейнер. Настоящий ELF начинается со смещения **110 855**; он извлечён в `native-analysis/libFUSION.embedded.so`, размер 706 160 байт. Похожий на ELF заголовок со смещения 6 находится в комментарии JPEG и не является полноценной библиотекой.

Для `libFUSION.so` статически выполнен инициализатор `DT_INIT` с применением Android-релокаций и ограниченной эмуляцией Linux-вызовов. Инициализатор вернулся; восстановлены расшифрованные исполняемые участки:

- `native-analysis/libFUSION.unpacked.so` — ELF для статического анализа; исходные данные и релокации сохранены, исполняемые сегменты заменены результатом распаковки.
- `native-analysis/fusion-emulated-image.bin` — образ памяти с базой `0x10000000`.
- `native-analysis/fusion-heap-*.bin` — временные области памяти эмуляции.
- `native-analysis/*.asm.gz` — сжатые текстовые инструкции ARM64. Их можно открыть через 7-Zip.
- `native-analysis/native-methods.json` — 262 объявления нативных методов Java, включая SDK.
- `native-analysis/*.json`, `*.strings.tsv` — сегменты, экспортируемые символы, строки и адреса.

Первичная распаковка проведена без запуска приложения и без обращения к его серверу. После этого исходный APK установлен в BlueStacks и активирован пользователем. Исполняемые сегменты FUSION из работающей игры побайтово совпали с результатом этой распаковки. Это подтверждает восстановленные машинные инструкции, но не правильность всех выводов декомпилятора.

Псевдокод Ghidra — материал для дальнейшего восстановления. Защитные переходы, виртуализированные участки, зашифрованные строки и отсутствующие типы могут оставаться. Названия `FUN_...`, типы `undefined...`, неразрешённые переходы и предупреждения не следует воспринимать как исходный авторский код. Границы функций также определены автоматически. Сводка охвата находится в `evidence/native-pseudocode-summary.json`.

Библиотеки игры, Flutter и сторонних SDK сохранены в бинарном виде. Для игровой `libg.so` дополнительно получен C-подобный псевдокод. Исходные авторские C/C++/Dart-проекты не получены. Файл `assets/kogcpfofggee.dat` сохранён в исходном виде; его содержимое не расшифровано.

## Проверка после активации

Исходный APK установлен в **BlueStacks 5.14.22.1003, Android 11 64-bit (Rvc64)**. Данные эмулятора находятся на `D:\BlueStacks_nxt`. После активации пользователем игра дошла до лобби; снимок — `evidence/bluestacks-lobby-after-activation.png`. Установленный APK совпал с предоставленным по SHA-256. Пересобранный неподписанный APK в эмулятор не устанавливался, бой не проверялся.

- `runtime-code/libFUSION.runtime.so` — оригинальные заголовки/данные ELF с исполняемыми сегментами из активированного процесса. Полностью совпадает с `native-analysis/libFUSION.unpacked.so`.
- `runtime-code/libg.runtime.so` — аналогичный снимок исполняемых сегментов игры. По сравнению с оригиналом изменены 775 байт на 48 страницах: 52 группы правок, из них 47 содержат абсолютный переход на переходник перехвата.
- `runtime-code/live-patches.tsv`, `evidence/live-patches.json` — адреса, исходные и изменённые байты. Назначение игровых функций не выдумывалось.
- `runtime-code/hook-code.json`, `hook-code.asm` — инструкции 47 переходников и двух общих диспетчеров. Указатели общих диспетчеров ведут обратно в восстановленный FUSION. Адреса относятся к конкретному запущенному процессу.
- `game-pseudocode/libg.runtime.so.pseudo.c` — первый проход по игровой библиотеке с наблюдаемыми перехватами. Автоанализ прерван по лимиту 300 секунд, экспорт также имел лимит; точные числа приведены в сводке.
- `game-pseudocode/libg.original.pseudo.c` — дополнительный проход после возврата наблюдаемых правок к байтам исходного APK; неизменённые успешные функции взяты из первого прохода. Это материал для чтения и ручной реконструкции, не готовые `.cpp` для сборки.
- `game-pseudocode/libg.retried.pseudo.c` — повторная попытка для шести функций, не обработанных основным проходом, с большим временем и запасным низкоуровневым режимом. Машинные инструкции этих функций — `libg.failed-functions.asm`. Итоговые числа и оставшиеся ошибки приведены в `evidence/game-pseudocode-summary.json`.

Всего в двух последних файлах получены тела **23 877 автоматически найденных функций** игры. Для двух функций декомпилятор так и не выдал C-подобное представление; инструкции сохранены. В основном тексте есть 8 271 предупреждение: количество успешных экспортов не означает правильность восстановленных типов, границ и логики каждой функции.

В ограниченном поиске по 1 452 доступным областям памяти не обнаружены дополнительные DEX, заголовки Lua или выбранные маркеры Frida-JavaScript. Совпадения общего текста `function ` относились к библиотечным строкам; найденный дополнительный ELF оказался копией `libg.so`. Это поиск выбранных сигнатур в одном состоянии процесса, он не доказывает отсутствие любого скрытого или зашифрованного кода. Сводка — `evidence/runtime-search-summary.json`.

**Отдельные исходники Frida `.js` не найдены.** Строки `frida` и `gum-js-loop` присутствуют в контейнере/скрытом ELF, но сами по себе не являются скриптом или доказательством работающего JS-движка. Найденные нативные перехваты сохранены отдельно; их принадлежность конкретному движку не утверждается.

В материалы не включены данные активации, настройки аккаунта или дамп кучи процесса. Снимки ELF для анализа не проверялись как подмена библиотек при запуске.

## Что проверено

- Apktool успешно декодировал и пересобрал проект.
- Все 35 956 файлов `assets/` и `lib/`, суммарно 1 838 062 867 байт, совпали с оригиналом по SHA-256 после пересборки.
- Для каждого из четырёх DEX совпали классы, родительские классы, интерфейсы, таблицы полей и методов, объявления полей/методов, флаги доступа и наличие тела метода. Это проверка структуры и упаковки, а не независимое доказательство эквивалентности всех инструкций.
- CRC всего собранного ZIP/APK прошёл проверку.
- Контрольные SHA-1 и Adler-32 всех исходных DEX корректны.
- Повторная распаковка FUSION дала тот же ELF, что был передан в Ghidra (MD5 `642672876db513f702ec5ea4d12dfbae`).
- Исполняемые сегменты FUSION из активированной игры совпали с распаковкой; повторный снимок в лобби дал те же FUSION и `libg`.

Результаты: `evidence/validation.json`, `evidence/dex-and-smali.json`, `evidence/fusion-emulation.json`, `evidence/bluestacks-runtime-validation.json`, `evidence/runtime-code-capture.json`.

SHA-256 проверенного неподписанного APK: `ba827fab291f3f82927be02ac71113fe2845d38aedccebf82fdd9f37bd71a338`.

## Ошибки декомпиляции и повторный анализ

JADX завершился с 94 сообщениями об ошибках. В 34 Java-файлах есть явные маркеры ошибки или недекомпилированных методов. Всего в 1 375 файлах обнаружены предупреждения, ошибки либо сомнительные конструкции. Список — `evidence/java-review-required.json`. Отсутствие маркеров не доказывает правильность Java.

Для таких методов используйте соответствующий smali как сохранённое представление байткода. Повторно получить Java или более прямое представление инструкций:

```powershell
.\tools\decompile.ps1
.\tools\decompile.ps1 -Simple
```

Для Python-инструментов нужен Python 3.9+ и пакеты из `tools/requirements.txt`. Эти зависимости не нужны для пересборки APK.

```powershell
python -m pip install -r .\tools\requirements.txt
python .\tools\analyze_recovery.py --disassemble
python .\tools\unpack_fusion.py
python .\tools\verify_recovery.py 'C:\path\to\original.apk' '.\artifacts\Switchgear-69.252-v3.2-rebuilt-unsigned.apk'
```

Восстановление не включает серверную реализацию, исходный keystore, историю Git, исходные C/C++/Dart-проекты, утраченные комментарии и имена, либо гарантированно компилируемые исходники из нативного псевдокода.
